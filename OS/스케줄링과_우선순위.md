# CPU 스케줄링과 우선순위 역전

## 한 줄 정의
CPU는 하나인데 실행하려는 프로세스는 여러 개다. **누구에게 먼저 CPU를 줄지** 정하는 규칙이 CPU 스케줄링이다.

## 전체 흐름
CPU 스케줄링 → 우선순위 스케줄링 → 문제 1: 기아 → 문제 2: 우선순위 역전 → 해결: 우선순위 상속

---

## 1. 선점형 vs 비선점형
| | 비선점형 | 선점형 |
|---|---|---|
| 의미 | 한 번 CPU를 잡으면 **끝날 때까지** 실행 | 더 급한 프로세스가 오면 CPU를 **뺏을 수 있음** |
| 종류 | FCFS, SJF, HRN, 우선순위(비선점) | RR, SRTF, 우선순위(선점), 다단계 큐, 다단계 피드백 큐 |
| 특징 | 문맥 교환 적음, 응답이 늦을 수 있음 | 응답 빠름, 문맥 교환 오버헤드 |

- 암기: 비선점 **F·S·H·우**, 선점 **R·S·우·다**

---

## 2. 스케줄링 알고리즘

### FCFS (First Come First Served, 비선점)
- **먼저 온 순서대로** 실행한다. 은행 번호표와 같다.
- 장점: 가장 단순하고 공평하다.
- 단점: **컨보이 효과**. 실행 시간이 긴 작업이 앞에 있으면 짧은 작업들이 줄줄이 기다린다.
- 예: P1(10초) → P2(1초) → P3(1초) 순으로 오면 P2, P3는 1초짜리인데 10초 넘게 기다린다.

### SJF (Shortest Job First, 비선점)
- **실행 시간이 가장 짧은 작업부터** 실행한다.
- 장점: **평균 대기 시간이 최소**다.
- 단점: 긴 작업은 짧은 작업이 계속 들어오면 영원히 밀리는 **기아**가 생긴다. 실행 시간을 미리 알기도 어렵다.

### HRN (Highest Response ratio Next, 비선점)
- SJF의 기아를 보완한 방식이다.
- **우선순위 = (대기 시간 + 실행 시간) / 실행 시간**, 값이 **큰 것부터** 실행한다.
- 오래 기다릴수록 분자가 커져서 우선순위가 올라간다 → 자연스러운 에이징 효과.
- 예: 대기 10, 실행 5 → (10+5)/5 = **3** / 대기 2, 실행 1 → (2+1)/1 = **3** → 같으면 보통 먼저 온 것부터.

### 우선순위 스케줄링 (선점·비선점 모두 가능)
- 프로세스마다 **중요도 번호**를 매기고 높은 것부터 실행한다. (보통 숫자가 작을수록 높지만 문제 조건 확인)
- 예 (숫자가 작을수록 높음):

| 프로세스 | 도착 | 실행 시간 | 우선순위 |
|---|---|---|---|
| P1 | 0 | 5 | 3 |
| P2 | 1 | 3 | 1 |
| P3 | 2 | 2 | 2 |

  - 비선점: P1(0~5) → P2(5~8) → P3(8~10)
  - 선점: P1(0~1) → P2(1~4) → P3(4~6) → P1(6~10)
- 단점: **기아**, 그리고 선점형에서는 **우선순위 역전**

### RR (Round Robin, 선점)
- 정해진 시간(**타임 퀀텀**)만큼씩 **돌아가며** 실행한다. 시간이 끝나면 큐의 맨 뒤로 간다.
- 장점: 공평하고 **응답 시간이 짧다** → 대화형 시스템에 적합.
- 단점: 퀀텀이 **너무 작으면** 문맥 교환이 많아 오버헤드가 커지고, **너무 크면** FCFS와 같아진다.

### SRTF (Shortest Remaining Time First, 선점)
- SJF의 **선점 버전**. **남은 실행 시간**이 가장 짧은 작업을 실행한다.
- 더 짧은 작업이 도착하면 지금 작업을 밀어낸다.
- 장점: 평균 대기 시간이 짧다.
- 단점: 긴 작업 **기아**, 문맥 교환이 많다.

### 다단계 큐 (MLQ, Multi-Level Queue, 선점)
- 준비 큐를 **여러 개로 나누고** 큐마다 우선순위를 준다. (예: 시스템 > 대화형 > 일괄 처리)
- 큐마다 다른 알고리즘을 쓸 수 있다. (예: 위 큐는 RR, 아래 큐는 FCFS)
- 단점: 프로세스가 **큐 사이를 이동할 수 없어서** 아래 큐는 기아가 생긴다.

### 다단계 피드백 큐 (MLFQ, 선점)
- 다단계 큐에서 **큐 사이 이동을 허용**한 방식이다.
- CPU를 오래 쓰는 작업은 **아래 큐로 내리고**, 오래 기다린 작업은 **위로 올린다(에이징)**.
- 장점: 기아를 완화하고 가장 유연하다 → 실제 OS에서 많이 쓴다.
- 단점: 큐 개수, 퀀텀 등 설정이 복잡하다.

### 한눈에 비교
| 종류 | 방식 | 기준 | 핵심 장점 | 핵심 단점 |
|---|---|---|---|---|
| FCFS | 비선점 | 도착 순서 | 단순 | 컨보이 효과 |
| SJF | 비선점 | 실행 시간 짧은 순 | 평균 대기 최소 | 기아 |
| HRN | 비선점 | (대기+실행)/실행 큰 순 | SJF 기아 보완 | 계산 부담 |
| 우선순위 | 둘 다 | 우선순위 높은 순 | 중요 작업 우선 | 기아, 역전 |
| RR | 선점 | 타임 퀀텀씩 순환 | 응답 시간 짧음 | 퀀텀 설정 |
| SRTF | 선점 | 남은 시간 짧은 순 | 대기 시간 짧음 | 기아, 문맥 교환 |
| MLQ | 선점 | 큐별 우선순위 | 작업별 정책 | 큐 이동 불가 → 기아 |
| MLFQ | 선점 | 큐 이동 가능 | 기아 완화, 유연 | 설정 복잡 |

## 3. 문제 1: 기아 (Starvation)
- 높은 우선순위가 계속 들어오면 낮은 우선순위는 **영원히 차례가 안 온다.**
- 생기는 곳: SJF, SRTF, 우선순위, MLQ
- **해결: 에이징(Aging)** → 오래 기다릴수록 우선순위를 올려 준다. (HRN, MLFQ에 들어 있는 아이디어)

### 우선순위를 정하는 방식
- **정적 우선순위**: 처음 정한 값을 계속 쓴다 → 단순하지만 기아가 생기기 쉽다.
- **동적 우선순위**: 실행 중에 값이 바뀐다 → 에이징, MLFQ

## 4. 문제 2: 우선순위 역전 (Priority Inversion)
**선점형 우선순위 스케줄링 + 공유 자원(락)**이 만나면 생긴다.

| 작업 | 우선순위 | 필요한 것 |
|---|---|---|
| L | 낮음 | CPU + **락** |
| M | 중간 | **CPU만** (락 필요 없음) |
| H | 높음 | CPU + **같은 락** |

### 발생 과정
1. L이 실행되다가 **락을 잡는다.**
2. H가 도착해 L을 선점한다. 그런데 락이 L에게 있어서 **H는 대기(Blocked) 상태**가 된다.
3. 실행 가능한 건 L뿐이라 L이 다시 실행된다.
4. M이 도착한다. 스케줄러는 **준비 상태인 작업 중에서만** 고른다. H는 대기 중이라 후보가 아니다. L과 M 중 M이 높으니 **M이 L을 선점**한다.
5. M이 실행되는 동안 L은 락을 못 풀고, H는 계속 기다린다.

**결과:** 가장 중요한 H가 락과 상관없는 M 때문에 늦어진다 → 우선순위가 **뒤집힘**

| 시점 | 실행 중 | 준비 큐 | 대기 |
|---|---|---|---|
| L이 락을 잡음 | L | | |
| H 도착, 락 요청 실패 | L | | H (락 대기) |
| M 도착 | **M** (L을 선점) | L | H |
| M 끝날 때까지 | M | L | H ← 계속 기다림 |

### 왜 비선점형에서는 안 생길까
4단계에서 M이 L을 밀어낼 수 없다. L이 끝까지 실행해 락을 풀면 바로 H 차례가 된다.
대신 비선점형은 긴급한 H도 L이 끝날 때까지 무조건 기다려야 한다.
실시간 시스템(RTOS)은 긴급 작업을 바로 처리해야 해서 **선점형**을 쓰므로 이 문제를 해결해야 한다.

---

## 5. 해결: 우선순위 상속 (Priority Inheritance)
**H가 L의 락을 기다리기 시작하는 순간, L의 우선순위를 H만큼 올린다.**
- M이 와도 L(지금은 H급)을 밀어낼 수 없다.
- L이 빨리 끝내고 락을 풀면 **원래 우선순위로 돌아간다.**
- H가 바로 락을 받아 실행된다.

```
상속 없음: L(락) → H 대기 → M 실행 → L 해제 → H 실행           ❌ H가 늦음
상속 있음: L(락) → H 대기 → L(H급) 실행 → L 해제 → H 실행 → M 실행   ✅
```

### 비슷한 방법: 우선순위 상한 (Priority Ceiling)
| | 우선순위 상속 | 우선순위 상한 |
|---|---|---|
| 언제 올리나 | H가 **기다리기 시작할 때** | 락을 **잡는 순간** 바로 |
| 얼마나 올리나 | 기다리는 작업의 우선순위만큼 | 그 락을 쓸 수 있는 작업 중 **최고** 우선순위만큼 |
| 특징 | 필요할 때만 올려서 효율적 | 미리 올려서 데드락 예방에도 도움 |

---

## 내 말로 설명하기
> CPU 스케줄링은 CPU를 어떤 프로세스에 먼저 줄지 정하는 규칙으로, 끝날 때까지 실행하는
> 비선점형과 중간에 뺏을 수 있는 선점형이 있다. 우선순위 스케줄링은 낮은 작업이 계속 밀리는
> 기아가 생겨 에이징으로 해결한다. 또 선점형에서 낮은 작업이 잡은 락을 높은 작업이 기다리는
> 사이 중간 작업이 끼어드는 우선순위 역전이 생기는데, 락을 가진 작업에 높은 우선순위를
> 잠시 물려주는 우선순위 상속으로 해결한다.
