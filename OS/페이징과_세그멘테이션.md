# 페이징과 세그멘테이션

## 한 줄 정의
둘 다 **프로그램을 나눠서 메모리에 올리는 방법**이다. 나누는 기준이 다르다.

## 비교
| | 페이징 | 세그멘테이션 |
|---|---|---|
| 분할 단위 | **고정** 크기 (페이지 / 프레임) | **가변** 크기 (코드, 데이터, 스택 등 논리 단위) |
| 단편화 | **내부** 단편화 | **외부** 단편화 |
| 주소 | 페이지 번호 + 오프셋 | 세그먼트 번호 + 오프셋 |
| 변환 테이블 | 페이지 테이블 | 세그먼트 테이블 |

- 주소 변환을 빠르게 하는 캐시: **TLB**
- 둘을 합친 방식: 페이지드 세그멘테이션

## 왜 그런 단편화가 생길까
- **페이징**: 모든 칸 크기가 같아서 빈 프레임 어디에든 들어간다 → 외부 단편화 없음.
  대신 마지막 페이지가 꽉 차지 않으면 그 칸 안이 남는다 → **내부** 단편화
- **세그멘테이션**: 크기에 딱 맞게 잘라서 칸 안 낭비는 없다.
  대신 크기가 제각각인 조각이 들어갔다 나오면 사이사이 애매한 빈틈이 생긴다 → **외부** 단편화

## 비유
- 페이징 = **같은 크기 택배 상자**에 짐 나누기 (마지막 상자가 덜 참)
- 세그멘테이션 = **짐 크기에 맞춘 상자** (창고에 상자 사이 빈틈이 생김)

## 관련 개념
- **스래싱**: 페이지 교체가 너무 잦아 CPU 이용률이 급감 → 워킹셋 유지로 완화
- **페이지 교체**: FIFO / LRU(가장 오래 안 쓴 것) / LFU(가장 적게 쓴 것) / OPT(이론상 최적)

## 내 말로 설명하기
> 페이징은 고정 크기로 나눠 외부 단편화는 없지만 내부 단편화가 생기고,
> 세그멘테이션은 의미 단위인 가변 크기로 나눠 내부 단편화는 없지만 외부 단편화가 생긴다.
