# 뮤텍스 세마포어 스핀락
## 한 줄 정의
락은 **여러 스레드가 공유 자원(임계 구역)에 동시에 들어가지 못하게 막는 도구**다.
종류마다 **몇 개까지 들어갈 수 있는지**와 **기다리는 방식**이 다르다.

## 1. 뮤텍스 (Mutex)
- **딱 1개**의 스레드만 들어갈 수 있다
- **소유권이 있다** → 잠근 스레드만 풀 수 있다
- 못 잡으면 **잠들어서(Sleep)** 기다린다 → CPU를 양보
- 소유자가 분명해서 **우선순위 상속** 적용 가능
- 비유: 화장실 열쇠 하나. 들어간 사람이 직접 열쇠를 들고 나와야 한다

## 2. 세마포어 (Semaphore)
- 정수 S로 **동시에 들어갈 수 있는 개수**를 관리
  - **P(wait)**: S를 1 감소, 0이면 대기
  - **V(signal)**: S를 1 증가, 기다리던 스레드를 깨움
- **이진 세마포어**: S가 0 또는 1 → 뮤텍스와 비슷
- **카운팅 세마포어**: S = N이면 **최대 N개** 동시 진입 (예: DB 연결 5개 나눠 쓰기)
- **소유권이 없다** → 다른 스레드가 V해도 된다 → **신호(이벤트) 전달**에도 사용
- 비유: 주차장 빈자리 전광판

## 3. 스핀락 (Spinlock)
- 못 잡으면 잠들지 않고 **계속 확인하며(바쁜 대기, Busy Waiting)** 기다린다
- 장점: 잠들고 깨어나는 **문맥 교환 비용이 없다** → 락을 **아주 짧게** 잡을 때 빠름
- 단점: 기다리는 동안 **CPU 낭비**
- 주로 **멀티코어**에서 사용 (싱글코어에서는 락을 가진 스레드가 실행될 수 없어 의미 없음)
- 비유: 화장실 앞에서 계속 문고리를 돌려 보며 서서 기다리기

## 4. 읽기-쓰기 락 (Read-Write Lock)
- **읽기는 여러 스레드가 동시에**, **쓰기는 한 스레드만**
- 읽기는 데이터를 바꾸지 않아 동시에 해도 안전하다
- **읽기가 많고 쓰기가 적을수록 효율적** (예: 설정값 조회, 캐시)
- 단점: 읽기가 계속 들어오면 **쓰기 스레드가 기아**에 빠질 수 있다
- 비유: 도서관 책은 여럿이 같이 볼 수 있지만 수정할 때는 혼자 가져간다

### ⚠️ 헷갈렸던 점
- 읽기가 많으면 비효율적인 게 **아니다** → 오히려 읽기가 많을 때 쓰라고 만든 락
- 단점은 "쓰기 기아"

## 5. 모니터 (Monitor)
- 락 + 조건 변수를 **언어 차원에서 묶어 둔** 고수준 동기화 도구
- 개발자가 직접 lock/unlock을 하지 않아 실수가 적다
- 예: Java의 `synchronized`, `wait()` / `notify()`

## 한눈에 비교
| | 동시 진입 | 기다리는 방식 | 소유권 | 주 용도 |
|---|---|---|---|---|
| 뮤텍스 | 1개 | 잠들어서 대기 | **있음** | 공유 자원 보호 |
| 이진 세마포어 | 1개 | 잠들어서 대기 | 없음 | 신호 전달, 동기화 |
| 카운팅 세마포어 | N개 | 잠들어서 대기 | 없음 | 개수가 정해진 자원 관리 |
| 스핀락 | 1개 | **바쁜 대기** | 있음 | 아주 짧은 임계 구역, 멀티코어 |
| 읽기-쓰기 락 | 읽기 N / 쓰기 1 | 잠들어서 대기 | 있음 | 읽기가 많은 자원 |
| 모니터 | 1개 | 잠들어서 대기 | 있음 | 언어 수준 동기화 (Java) |

## 뮤텍스 vs 이진 세마포어
둘 다 1개만 들어가지만 **소유권**이 다르다.
- 뮤텍스: **잠근 사람만** 풀 수 있다 → 우선순위 상속 가능, 자원 보호용
- 이진 세마포어: **아무나** 풀 수 있다 → "A 끝나면 B 시작" 같은 신호용

## 임베디드에서 주의할 점
- **인터럽트 처리 함수(ISR)** 안에서는 잠들면 안 된다 → ISR에서 뮤텍스 사용 불가
  - 대신 스핀락이나 인터럽트 비활성화, 또는 ISR에서 세마포어로 **신호만 주고** 처리는 태스크에 맡긴다
- 우선순위 역전을 막으려면 **우선순위 상속을 지원하는 뮤텍스**를 쓴다 (FreeRTOS 등)

## 내 말로 설명하기
> 뮤텍스는 한 번에 하나의 스레드만 자원에 접근하게 하는 락으로, 잠근 스레드만 해제할 수 있는 소유권이 있다. 
> 세마포어는 정수 값으로 N개까지 동시 접근을 허용하고 소유권이 없어 신호 전달에도 쓴다.
> 스핀락은 잠들지 않고 계속 확인하며 기다려 문맥 교환 비용은 없지만 CPU를 낭비하므로 아주 짧은 임계 구역에 적합하다.
