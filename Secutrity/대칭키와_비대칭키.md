# 대칭키와 비대칭키

## 비교
| | 대칭키 (비밀키) | 비대칭키 (공개키) |
|---|---|---|
| 키 | 암호화 키 = 복호화 키 (**같음**) | 공개키 + 개인키 **쌍** |
| 속도 | **빠름** | 느림 |
| 단점 | **키를 안전하게 전달하기 어려움**, 키가 많이 필요 (n(n−1)/2개) | 계산이 복잡함 |
| 필요한 키 수 | n(n−1)/2 | 2n |
| 알고리즘 | **DES, AES, SEED, ARIA** | **RSA, ECC, DSA** |

## ⚠️ 헷갈렸던 점
- **RSA는 비대칭키다.** (만든 세 사람 Rivest, Shamir, Adleman의 앞글자)
- "키를 안전하게 전달하기 어렵다"는 대칭키의 **맞는 설명(단점)**이다.

## 어떤 키로 암호화할까
| 목적 | 암호화 | 복호화 |
|---|---|---|
| **기밀성** (B만 읽게) | **B의 공개키** | B의 개인키 |
| **전자서명** (A가 보냈다는 증명) | **A의 개인키** | A의 공개키 |

- 공개키 = 누구나 가진 **자물쇠**, 개인키 = 나만 가진 **열쇠**

## 실제 사용: 하이브리드 (HTTPS)
느린 공개키 방식으로 **대칭키만 안전하게 전달**하고, 이후 데이터는 빠른 대칭키로 주고받는다.

## 내 말로 설명하기
> 대칭키는 같은 키로 암호화·복호화해 빠르지만 키 전달이 어렵고, 비대칭키는 공개키로
> 잠그고 개인키로 열어 키 전달 문제가 없지만 느리다. 그래서 실제로는 두 방식을 섞어 쓴다.
