# Day 01: 프로세스 메모리 배치 (스택, 힙, 데이터, 코드)

## 목표
변수의 종류에 따라 메모리의 어느 영역에 놓이는지 주소를 출력해서 직접 확인한다.

## 환경
- 보드: Jetson Xavier NX (ARM64, Ubuntu 20.04, L4T R35.6.4)
- 컴파일: `gcc -Wall -O0 -g memory.c -o memory`

## 실험 대상
| 변수 | 종류 | 예상 영역 |
|---|---|---|
| `g_var` | 전역 변수 (초기값 1) | 데이터 (.data) |
| `s_var` | static 지역 변수 (초기값 2) | 데이터 (.data) |
| `main_local` | main의 지역 변수 | 스택 |
| `other_local` | 다른 함수의 지역 변수 | 스택 |
| `heap` | `malloc` 할당 메모리 | 힙 |
| `main` | 함수 자체 | 코드 (.text) |

## 결과

### ASLR 켠 상태 (2회 실행)
| 변수 | 1회차 | 2회차 |
|---|---|---|
| main_local | 0xffffcb47c0ec | 0xffffe9a3440c |
| other_local | 0xffffcb47c0c4 | 0xffffe9a343e4 |
| heap | 0xaaaac88922a0 | 0xaaab104ae2a0 |
| s_var | 0xaaaaab421014 | 0xaaaae3b61014 |
| g_var | 0xaaaaab421010 | 0xaaaae3b61010 |
| main 함수 | 0xaaaaab410930 | 0xaaaae3b50930 |

### ASLR 끈 상태 (`setarch -R`, 2회 실행, 두 번 모두 동일)
| 변수 | 주소 |
|---|---|
| main_local | 0xfffffffff33c |
| other_local | 0xfffffffff314 |
| heap | 0xaaaaaaab22a0 |
| s_var | 0xaaaaaaab1014 |
| g_var | 0xaaaaaaab1010 |
| main 함수 | 0xaaaaaaaa0930 |

### 메모리 배치
```
높은 주소  0xffff...    [스택]   main_local, other_local (아래로 자람)
                        (공유 라이브러리 등)
           0xaaaa c8..  [힙]     malloc (위로 자람)
           0xaaaa ab42  [데이터] g_var, s_var
낮은 주소  0xaaaa ab41  [코드]   main
```

## 분석

1. **주소 순서는 스택 > 힙 > 데이터 > 코드**로, 리눅스의 일반적인 메모리 배치와 일치한다.
2. **스택은 아래로 자란다.** `other_local`이 `main_local`보다 0x28(40바이트) 작다. `other_func`가 호출되면서 스택 프레임(지역 변수, 복귀 주소, 이전 프레임 포인터)만큼 스택이 아래로 늘어났다.
3. **ASLR**: 켜면 실행할 때마다 주소가 바뀌고, 끄면 매번 같다. 운영체제가 보안(주소 예측 방지)을 위해 배치를 무작위화한다는 직접 증거다.
4. **주소 끝 3자리(16진수)는 ASLR을 켜도 바뀌지 않는다.** (`main`은 항상 `...930`) ASLR이 페이지(4KB = 0x1000) 단위로 위치를 옮기기 때문에 페이지 안의 오프셋은 유지된다.
5. **코드와 데이터 사이 거리는 항상 같다.** (`g_var - main = 0x106e0`) 같은 실행 파일에 들어 있어 한 덩어리로 움직인다. 반면 힙 시작 위치(`brk`)는 별도로 무작위화되어 데이터와의 거리가 매번 달라진다.
6. **ASLR을 끄면 힙은 데이터 영역 바로 다음 페이지에서 시작한다.** (`s_var` = `...b1014` → 힙은 `...b2000` 페이지) `+0x2a0`은 malloc의 관리용 데이터 공간이다.
7. **`g_var`와 `s_var`는 4바이트 간격으로 붙어 있다.** 둘 다 초기화된 정적 수명 변수라서 같은 `.data` 섹션에 연속 배치된다. `static` 지역 변수는 이름이 보이는 범위(스코프)만 함수 안으로 제한될 뿐, 저장 위치와 수명은 전역 변수와 같다.
8. **0xaaaa...와 0xffff...는 ARM64 리눅스의 특징이다.** 사용자 공간으로 48비트 가상 주소를 쓰며, 스택은 공간의 맨 위, PIE 실행 파일은 `0xaaaa aaaa...` 근처에 올라간다. 출력된 주소는 모두 **가상 주소**이며, MMU가 실제 물리 주소로 변환한다.

## 틀렸던 점 (기록)
| 처음 생각 | 실제 |
|---|---|
| `main`의 지역 변수는 코드 영역에 있다 | `main` **함수 자체**는 코드 영역, `main` **안의 지역 변수**는 스택에 있다 |
| 재실행 시 주소가 다른 이유: 이전 데이터가 메모리에 남아 있어서 | 프로세스가 끝나면 메모리는 모두 반납된다. 진짜 이유는 **ASLR** |
| 전역/static 변수가 붙어 있는 이유: 같은 "블럭"이라서 | 같은 **.data 섹션**에 링커가 순서대로 배치하기 때문 |
| 힙 위치가 바뀌는 이유: 무작위라서 | 힙 시작(`brk`)이 실행 파일과 **별도로** 무작위화되기 때문 |

## 추가 실험 (진행 예정)
- [ ] `other_func`에 `int arr[100];` 추가 → `other_local` 주소 변화량과 `arr` 위치 확인
- [ ] 초기값 없는 전역 변수(`int g_zero;`) 추가 → `.data`와 `.bss` 위치 비교
