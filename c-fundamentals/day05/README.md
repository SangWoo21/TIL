# Day 05: 비트 연산

## 목표
1. 비트 켜기, 끄기, 뒤집기, 확인하기 4가지 패턴
2. 여러 비트로 이루어진 필드에 값 쓰기와 꺼내기
3. 링 버퍼에서 쓰는 `i & (N-1)`이 `i % N`과 같은 이유
4. 부호 있는 타입에서 비트 연산이 위험한 경우

## 환경
- 보드: Jetson Xavier NX (ARM64, Ubuntu 20.04, gcc 9.4.0)
- 컴파일: `gcc -Wall -O0 -g bits.c -o bits`

## 핵심 개념: 스위치 8개짜리 패널
`uint8_t reg = 0;` = 스위치 8개(비트)가 달린 패널. 각 비트는 1(켜짐) 또는 0(꺼짐).
```
비트 번호:  7 6 5 4 3 2 1 0
reg:        0 0 0 0 0 0 0 0
```

| 연산 | 뜻 | 쓰임 |
|---|---|---|
| `a & b` | 둘 다 1이면 1 | 특정 비트 확인, 끄기 |
| `a \| b` | 하나라도 1이면 1 | 특정 비트 켜기 |
| `a ^ b` | 서로 다르면 1 | 특정 비트 뒤집기 |
| `~a` | 모든 비트 반전 | 마스크 뒤집기 |
| `a << n` | 왼쪽으로 n칸 | `1 << 3` = 3번 비트 위치 |
| `a >> n` | 오른쪽으로 n칸 | 원하는 비트를 맨 아래로 꺼내기 |

**주의: `&`(비트 AND)와 `&&`(논리 AND)는 다르다.** `&`는 비트 하나하나를 계산해 여러 비트짜리 숫자가 나오고, `&&`는 참/거짓(1 또는 0)만 나온다.

### 4가지 패턴
```c
reg |=  (1u << n);    // n번 비트 켜기
reg &= ~(1u << n);    // n번 비트 끄기
reg ^=  (1u << n);    // n번 비트 뒤집기
(reg >> n) & 1u       // n번 비트 확인 (0 또는 1)
```

## 실행 결과

```
전체 뒤집기 = 01111110 (0x7E, 126)

```

## 실험 1: 4가지 패턴
- 0번, 7번만 켜진 `10000001`을 `^ 0xFF`로 전부 뒤집으면 `01111110`. 5번 비트는 1.

## 실험 2: 필드에 값 쓰기 (레지스터 제어의 기본)
```c
ctrl = (ctrl & ~(0x7 << 2)) | (mode << 2);   // 2~4번 비트에 mode(5) 쓰기
```
```
비트 번호:  7 6 5 4 3 2 1 0
ctrl:       0 0 0 1 0 1 0 0   = 0x14 = 20
                  └─┬─┘
                 mode(101)
```
1. `ctrl & ~(0x7 << 2)`: 2~4번 자리를 먼저 **0으로 지운다.**
2. `| (mode << 2)`: 값을 2칸 밀어서 그 자리에 **쓴다.**
- 먼저 지우지 않으면 원래 있던 1이 남아 값이 섞인다.
- 꺼낼 때는 반대로: `(ctrl >> 2) & 0x7` = 5

### 일반 공식
```c
reg = (reg & ~(MASK << POS)) | ((val & MASK) << POS);   // 쓰기
val = (reg >> POS) & MASK;                               // 읽기
```
- **마스크는 필드 폭으로만 정해지고 위치와 상관없다.** 3비트 필드면 2~4번이든 4~6번이든 `0x7`. 바뀌는 것은 `POS`(미는 칸 수)뿐이다.
- `val & MASK`는 값이 필드보다 커서 옆 비트를 침범하지 않게 자르는 안전장치다.
- 예: 32비트 `reg`의 4~6번 비트에 3 쓰기
  ```c
  reg = (reg & ~(0x7u << 4)) | (3u << 4);
  ```

## 실험 3: 링 버퍼의 `i & (N-1)`
- N = 8일 때 `i % N`과 `i & (N-1)`의 결과가 **완전히 같다.**
- 이유: N-1 = 7 = `111`. `i & 7`은 아래 3비트만 남기는데, 8로 나눈 나머지가 바로 아래 3비트다.
  ```
  i = 10 = 1010
       &   0111
       =   0010 = 2   (10 % 8 = 2)
  ```
- **N이 2의 거듭제곱일 때만 성립한다.** N = 6이면 N-1 = 5 = `101`이라 가운데 비트가 빠진다. `6 & 5 = 4`이지만 `6 % 6 = 0`.
- **장점**: 나머지(`%`)는 나눗셈이라 여러 사이클이 걸리지만, `&`는 한 번에 끝난다. 인터럽트처럼 짧게 끝나야 하는 코드에 유리하다. 그래서 링 버퍼 크기를 64, 128처럼 2의 거듭제곱으로 정한다.

## 실험 4: 부호 있는 타입의 위험
### 오른쪽 시프트
```
s (int8_t,  -8):  11111000 >> 1 = 11111100 = -4    맨 앞을 1로 채움 (산술 시프트)
u (uint8_t, 248): 11111000 >> 1 = 01111100 = 124   맨 앞을 0으로 채움 (논리 시프트)
```
- 같은 비트라도 타입에 따라 결과가 다르다.
- 음수의 오른쪽 시프트는 C 표준이 정하지 않았다. gcc는 1로 채우지만 컴파일러마다 다를 수 있다.

### 최상위 비트
- `1`은 부호 있는 32비트 `int`. `1 << 31`은 부호 비트에 1이 들어가 음수(-2147483648)가 되며, C 표준상 **정의되지 않은 동작**이다.
- `1u`는 `unsigned int`라 `1u << 31` = 2147483648로 정상이다.
- 32번 이상 비트는 `1ULL << 40`처럼 64비트 타입을 쓴다.

### 결론: 비트 연산에는 부호 없는 타입을 쓴다
1. 오른쪽 시프트가 항상 0으로 채워져 예측대로 동작한다.
2. 최상위 비트를 다뤄도 정의되지 않은 동작이 없다.
3. 부호 없는 타입은 넘치면 0부터 다시 도는 동작이 표준으로 정해져 있다. (부호 있는 타입의 overflow는 정의되지 않은 동작)
4. 레지스터는 원래 "부호 없는 비트 묶음"이므로 `uint32_t`가 의미와도 맞다.

## 틀렸던 점 (기록)
| 처음 생각 | 실제 |
|---|---|
| `i & (N-1)`은 결과가 1과 0으로만 나온다 | `&`는 **비트별** 연산이라 여러 비트짜리 숫자가 나온다. 0/1만 나오는 것은 `&&` |
| N = 8일 때 `i % N`과 `i & (N-1)`은 다르다 | N이 2의 거듭제곱이면 **같다** (N-1이 하위 비트가 모두 1인 마스크) |
| ctrl에 101을 그냥 넣는다 | 2칸 밀어서 **2~4번 자리**에 넣는다. 먼저 그 자리를 지운다 |
| 4~6번 비트의 마스크를 몰랐음 | 마스크는 필드 폭(3비트 → `0x7`)으로 정해지고, **위치는 시프트 칸 수**로만 바뀐다 |
| `-8 >> 1`을 2칸 미는 것으로 읽음 | 1칸이다. 결과 -4 (산술 시프트) |
| `1u`의 의미를 몰랐음 | `unsigned int` 상수. `1 << 31`은 부호 있는 int라 음수 + 정의되지 않은 동작 |
| unsigned를 쓰는 이유: 정상 연산을 위해 | 구체적으로: 오른쪽 시프트가 0으로 채워짐, 최상위 비트 안전, overflow 동작이 정의됨 |

## 면접 대비 한 줄 요약
- "레지스터의 필드를 바꿀 때는 마스크로 해당 자리를 먼저 지운 뒤 값을 시프트해서 OR합니다. 링 버퍼 크기를 2의 거듭제곱으로 두면 N-1이 하위 비트 마스크가 되어 나눗셈 대신 AND로 인덱스를 되돌릴 수 있습니다. 비트 연산은 시프트와 최상위 비트에서 정의되지 않은 동작을 피하려고 부호 없는 타입으로 합니다."
